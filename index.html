■ DATA & METHODOLOGY

DOSSIER ID SCHEME
Bizarre-subject dossiers carry permanent IDs of the form JAH-LEAK-B###### (e.g. JAH-LEAK-B0001). IDs are sequential, permanent, and never re-used; every ID listed in the sitemap opens its dossier at ?dossier=<id>. Spec dossiers use JAH-SPEC-###### IDs and open the same way; patent dossiers use the public patent publication number as their ID. Every ID is stable across versions.
CLASSIFICATION SYSTEM
Each dossier carries a FILE CLASSIFICATION tag and a classification banner. Dossier types: BIZARRE FILE (speculative analysis), SPEC DOSSIER (original draft by Justin Addam Higgins, JAH — draft, ready to file, not a granted patent), PATENT DOSSIER (real public record, summarized from the public domain). Classification labels are per-file and travel with the file in every download (dossier.txt, dossier.json, AI disc, AI thumbdrive).
NAME & SCOPE — WHAT "WIKI LEAKS" MEANS HERE
The name Wiki Leaks is this archive's own title — it does not mean every file is leaked or confidential material. BIZARRE FILE and SPEC DOSSIER records are the JAH system's own internally published files (the organization's own internal files, declassified-by-the-organization framing) — they were never secret government documents and were never "leaked" from anywhere. Only PATENT DOSSIER records summarize real public records, and they are labeled PUBLIC RECORD on the file itself, never presented as leaked or classified. If a file is publicly available, it is labeled public; the TOP SECRET styling on JAH-N internal files is creative flavor for a system record, not a real classification.
SOURCE / PROVENANCE PER RECORD
Every dossier carries a machine-readable FILE CLASSIFICATION & PROVENANCE section and a per-section provenance tag — [PUBLIC RECORD], [JAH ANALYSIS], [SPECULATIVE], [JAH ORIGINAL], [JAH OFFICIAL], or [UNKNOWN] — plus a SOURCES / WITNESSES / REFERENCES section where public-record material is used. The complete file package download includes dossier.json with full provenance and a content hash.
STATIC INDEXES & FEEDS
For crawlers, AI indexers, and no-JS readers: full dossier archive (A–Z, lazy-loading), static category index (per-category counts + top dossiers), newest 100 dossiers, and the incremental JSON feed (newest 1,000 dossiers, chunked — regenerated by the 2h bizarre drip, so diffing it finds every new batch).
VERSIONING
Dossier records are stamped v1.0 (baseline); the version never rewrites history — corrections, if any, land in new versioned fields. Dossier content is hashed (CRC32 content hash shown in the badge section) so any copy can be verified byte-identical against the archive.
